Building a marketing site usually means stitching things together yourself. You pick a build tool. You pick a component library. You pick a CMS. Then you spend days, sometimes weeks, wiring them together, deciding what editors can change, building the integration layer, and maintaining it as both sides evolve.

The <a href="/templates/astro-component-starter" target="_blank" rel="noopener" title="Astro Component Starter">Astro Component Starter</a> cuts that work out. It's a complete, integrated component system — 30+ Astro components, a design token system, visual editing configuration, and <a href="https://astro-component-starter.cc/component-docs/" target="_blank" rel="noopener">built-in documentation</a> — ready to scaffold a marketing site in minutes. Think of it as building your own page builder, except you own every file and there's no platform ceiling.

## From scaffold to branded site

Start with the CLI:

```bash
npx create-astro-component-starter my-site-name
cd my-site-name
npm run dev
```

You immediately have a working site at `localhost:4321` with pages, a blog, navigation, and a full component documentation site. Out of the box, the design is intentionally neutral. It's meant to disappear into whatever brand you bring.

Design tokens handle the broad strokes: update CSS variables for colors, fonts, spacing, and the entire site shifts at once. That gets you most of the way. For the rest, every component's CSS is right there in your codebase — not hidden behind an abstraction layer, not locked in a package you can't touch. It's normal CSS in files you own, so branding work is just styling work.

## A page builder you control

Components are standard Astro component in your `src/components/` directory. The building-block components — buttons, headings, images, text blocks, form elements, layout grids — are simple on purpose. They're tuned for performance and accessibility, built on semantic HTML and vanilla CSS. The power is in composition.

Combine building blocks into page section components: heroes, feature showcases, testimonials, pricing grids, CTAs. Use the built-in component builder to prototype combinations without writing code, or compose them directly in your Astro files. Either way, the result is production-ready and configured for visual editing.

## Built for visual editing

Every component in the starter is pre-configured for CloudCannon's visual editor. That means your editors can click directly on elements on the page — a heading, an image, a call-to-action — and edit them in place, seeing their changes live on the actual site. No switching between a form and a preview. No guessing what the result will look like.

<Video type="youtube" videoId="XxSjWHoxGZg" title="Visual editing with the Astro Component Starter" />

But it goes beyond inline text editing. Editors can add, remove, and reorder entire sections on a page by picking from the components you've built, assembling pages from your component library without touching code. It's a page builder experience, except every component is yours, the output is a high-performance Astro site, and the content lives in your Git repository.

You decide exactly what editors can touch. Lock a layout down to text-only edits, open a section up so editors can add, remove, and reorder blocks, or give them full page building where they can chain together anything in the system. Every component is fully documented: developers can define the boundaries; editors work freely within them.

<img alt="Documented components and building blocks for the Astro Component Starter" loading="lazy" src="https://cc-dam.imgix.net/astro-component-starter-docs-shadow.png" />

If you're an agency, this goes further. Take the Component Starter, add the components you use on every project, wire in your layouts, set up your brand tokens — and you've built your own page builder, except you own the code and control the editing experience.

## What the community built in a week

To celebrate the launch, we ran the Astro Challenge — a one-week competition with a $4,500 prize pool, challenging developers to take the Component Starter and make it their own. Three winners each took home $1,500 USD, and the range of entries showed just how far you can push the Starter in a short time.

* **Felix Schneider** built <a href="https://github.com/trueberryless-org/trueberryless-org" target="_blank" rel="noopener">a landing page for his trueberryless-org ecosystem</a> with a train-themed design system and a modular architecture — Starlight plugin integration, automated template syncing, and a set of custom "wagon" components that slot together around a central layout.
* **Lawrence Sticks** created <a href="https://github.com/dev-lawrence/kairos-studio" target="_blank" rel="noopener">Kairos Studio</a>, a boutique brand agency site with a clear point of view: positioning-first design, a deliberately small client roster, and copy sharp enough to sell actual services.
* **David Kimball** went bold with <a href="https://github.com/davidvkimball/fluent" target="_blank" rel="noopener">SIGNAL</a>, a fictional growth marketing agency featuring animated mesh gradients, glassmorphism navigation, and a cyan-and-coral palette on deep black — seven pages and eleven blog posts, all with real content.

What stood out across all three was that the CloudCannon editing experience came through intact. Drag-and-drop page building, visual editing, structured content were all preserved, and that's the whole point of the Component Starter. You own the code, you control the design, and your editors still get a proper page builder experience at the end of it.

All three winning repos are public on GitHub — fork them, test them on CloudCannon, and see what's possible!
